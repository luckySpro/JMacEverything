# 2.0 关键决策（ADR）

每条决策：编号、日期、结论、原因、放弃的方案。改变决策时新增一条，不改旧条目。

## D-001 保留 C++ 引擎，经 FFI 由 Rust 调用（2026-10-24）
- **结论**：2.0 不重写搜索引擎；先把 C++ 引擎的 GCD/CoreFoundation 依赖换成跨平台实现，再用 `cxx` 桥接给 Rust。
- **原因**：引擎约 9,200 行、11,962 个测试全过，是产品速度的来源；重写风险高、周期长，而跨平台真正缺的只是扫描层和界面。
- **放弃**：纯 Rust 重写（可作为 3.0 方向，逐模块替换）。

## D-002 界面用 Tauri 2 + Vue 3（2026-10-24）
- **结论**：一套前端覆盖 Mac 和 Windows。
- **原因**：与系列产品技术栈一致；安装包小；Rust 端可直接复用核心。
- **放弃**：各平台原生界面（SwiftUI + WinUI，两份 UI 代码）；Electron（体积和内存大）。

## D-003 Windows 用只读索引服务读取 MFT/USN（2026-10-24，待确认）
- **结论**：安装时注册 `jme-indexer` 服务（只读），GUI 保持普通用户；无服务时降级为目录遍历。
- **原因**：MFT/USN 是 Windows 上秒级索引的唯一途径，且需要管理员权限；把特权限制在最小的只读组件里。
- **放弃**：让 GUI 以管理员运行（风险大、每次弹 UAC）。

## D-004 开发过程的数据保护（2026-10-24）
- **结论**：所有工作在 GitHub `v2` 分支上进行；每完成一个可描述的步骤就提交并推送；进度写入 PROGRESS.md；用 `scripts/checkpoint.sh` 统一完成「记录 + 提交 + 推送 + 校验远端」。
- **原因**：会话可能中断、本地机器可能不可用；以 GitHub 为唯一可信存档，任何时刻丢失的工作不超过一个步骤。
